## 실행과 화면

Flutter 프로젝트는 개발 사본 안의 `runline` 디렉터리다. 기존 `config/*.local.json`은 계속 Git에서 제외하며 내용을 출력하거나 커밋하지 않는다.

- 홈 START는 자유 러닝이다. 기존 목표 설정도 자유 러닝의 거리/시간 목표로 사용할 수 있다.
- 그림/프리셋 → 실제 서버의 OSM 추천 → 코스 선택 → 러닝 시작 흐름을 유지한다. mock/synthetic 결과로 코스 러닝을 시작하지 않는다.
- 파랑은 미통과 추천 코스, 초록은 통과가 확인된 코스, 보라는 그림 루트 러닝의 실제 GPS 궤적이다. 자유 러닝의 실제 궤적은 초록이다.
- 같은 물리적 구간의 반복 회차는 진행 순서를 따로 관리한다. 미통과 회차가 남으면 두꺼운 파란 선의 외곽이 초록 선과 함께 남는다.
- 청록 마커는 필터를 통과한 마지막 현재 위치다. GPS 불량/중단 상태에서는 새 위치처럼 움직이지 않는다.
- 주황 화살표는 코스상 다음 약 15m의 진행 방향이며, 교차로 회전 지시가 아니다.
- 추적 중에는 위치를 따라간다. Android 지도 제스처 및 Web drag/wheel은 추적을 중지한다. 현재 위치 버튼은 추적과 근거리 확대를 다시 활성화한다.
- 일시정지/숨김/신호 단절 후에는 측정과 통과 증거를 새 구간으로 시작하여 직선을 연결하지 않는다.
- 종료 화면의 기록 상세, 홈의 러닝 기록에서 로컬 기록을 조회한다. 상세에서 추천 코스와 실제 궤적 표시를 각각 전환할 수 있다.

## 판정과 설정

`route_navigation.dart`의 `RouteNavigationSettings`에서 코스 통과와 이탈 기준을 별도로 관리한다.

| 설정 | 기본값 |
| --- | --- |
| 코스 표본 간격 | 최대 5m |
| 통과 허용 거리 | 10m |
| 통과 판정에 사용하는 GPS 정확도 반경 | 최대 12m |
| 이탈 거리 / 복귀 거리 | 30m / 18m |
| 이탈 확정 | 연속 3개 정확한 fix |
| 일반 전방 매칭 범위 / 후퇴 범위 | 35m / 12m |
| 연속 통과 증거의 최대 시간 간격 | 15초 |

기존 `RunningMeasurement`의 GPS 필터는 그대로 사용한다. 코스 통과 판정은 그보다 보수적이므로 이동 거리가 증가해도 코스 통과가 보류될 수 있다. 화면에 GPS 정확도에 따른 보류 상태를 표시한다.

거리 누적값으로 코스를 색칠하지 않는다. GPS를 코스 선분에 투영하고 현재 회차의 제한된 탐색 범위·시간·실제 이동 속도·전진량을 비교한다. 연속 fix 사이에서 실제 GPS 선분 가까이에 있는 코스 구간만 통과 범위에 합친다. 통과 범위는 합집합으로 저장하여 중복 거리를 더하지 않는다.

초기에는 코스 시작 부분에서 순서대로 진입해야 한다. 시작점에서 약 3m 이내의 코스상 위치를 확인하며 시작점 앞 구간을 임의로 완료하지 않는다. 이탈/중단 후 먼 지점으로 재합류하면 연속 3개의 이동 fix와 모호하지 않은 코스 위치를 확인한 뒤 커서만 옮긴다. 건너뛴 구간은 미통과로 남는다. 교차·중복 구간에서 회차가 모호하면 진행을 보류한다.

현재 위치의 코스상 투영값과 순서 탐색 커서를 분리해, 뒤로 이동해도 위치 표시는 갱신하되 나중 회차로 갑자기 이동하지 않는다. 진행률은 확인된 통과 길이 / 코스 좌표의 기하학적 전체 길이이고, 미통과 거리는 전체 길이에서 확인된 통과 길이를 뺀 값이다. 서버 카드의 코스 거리와 좌표로 계산한 길이는 다를 수 있다. 완주는 모든 구간이 통과 증거로 덮인 경우이며 자동으로 러닝을 종료하지 않는다.

GPS만으로 인접한 평행 도로·다층 도로·정지 드리프트를 완벽히 구별할 수 없다. 정확도가 나쁘거나 구간이 모호할 때는 과대 완료보다 판정 보류를 우선한다. 설정값은 실제 기기/코스에서 조정해야 한다.

## 저장 호환성과 팀 인터페이스

Sembast 저장소·DB 이름·기존 schema 1을 유지한다. 선택적인 `navigation` 확장에 버전, 표본 간격, 코스 길이, 탐색 커서와 실제 통과 범위를 저장한다. 선택 코스, GPS 점, 구간 시작 인덱스, 활동 시간, 날짜, 거리, 목표는 기존 형식을 유지한다. 기록을 삭제하거나 일괄 변환하지 않는다. 이전 기록은 계속 읽고, 통과 정보는 '없음'으로 표시한다. 과거 이동 거리에서 통과율을 추측하지 않는다.

Activity 담당자는 기존 인터페이스를 그대로 사용할 수 있다.

```dart
final repository = await RunningHistory.open();
final records = await repository.list(finished: true);
final record = await repository.read(id);
// 선택적 값: record?.courseProgress, record?.courseCompleted
// 평균 페이스는 기존 거리/활동 시간 엔진을 재사용: record?.averagePace
// 독립 화면:
RunningRecordDetailScreen(recordId: id, repository: repository);
```

앱 공용 저장소를 화면 단위로 close하지 않는다. 기존 revision/완료 기록 보호를 유지하며, 저장 실패 재시도는 초기 저장소 열기가 실패한 뒤에도 현재 세션의 GPS를 저장할 수 있다. 앱 종료 전 아직 커밋되지 않은 체크포인트는 기존과 같이 유실 가능하다(약 5초 + 저장 지연). Web 기록은 origin/port에 종속된다.
